# Coordinate migration contract

LitEngine uses an Unreal-style authoring convention by default: **+X forward, +Y right, +Z up**. This is a breaking default change released on the `3.0.0-beta.0` major-version line. Existing PlayCanvas projects can retain the old Y-up behavior by explicitly selecting `legacy` before initialization. Conversion and scene-format APIs below are explicit migration/preview tools; do not mix converted values with legacy objects. Do not change `Vec3.cross`, quaternion math or GPU clip space based solely on a handedness label.

## Final target

- **3D world:** +X forward, +Y right, +Z up; XY ground plane. The basis conversion does not change world units. Rotation arrays use UE's `TRotator::Euler()` XYZ order: Roll about X, Pitch about Y, Yaw about Z, in degrees. This differs from PlayCanvas intrinsic XYZ Euler angles.
- **2D game world (Paper2D-style):** XZ side-view plane, X horizontal, Z vertical, Y depth. This is a plane in the 3D world, not screen coordinates.
- **2D screen UI (UMG-style):** a top-left-anchored canvas has +X right, +Y down. Anchor-relative coordinates depend on their anchors. Screen-space runtime UI and world-space Screen UI use top-left/+Y-down layout semantics in Unreal mode. A world-space Screen is mapped onto the Unreal YZ plane, with UI horizontal along local +Y and UI vertical along local −Z; the screen root remains a normal 3D world transform. Legacy applications keep their existing behavior.

## Legacy 3D basis conversion

The public helpers in `src/core/math/coordinate-conversion.js` map legacy PlayCanvas (X right, Y up, −Z forward) to the target:

| Quantity | Legacy → target | Target → legacy |
| --- | --- | --- |
| Position/direction | `(−z, x, y)` | `(y, z, −x)` |
| Scale magnitudes | `(z, x, y)` | `(y, z, x)` |
| Orientation/matrix | `B · R · B⁻¹` | `B⁻¹ · R · B` |

`det(B) = −1`. For orientation quaternions, legacy `(qx,qy,qz,qw)` becomes `(qz,−qx,−qy,qw)`. Do not reorder Euler triples or substitute a negative scale. Full affine matrix conversion includes shear. Geometry conversion must also reverse triangle winding and tangent handedness.

`unrealEulerToRotation` and `unrealRotationToEuler` follow UE 5.8 `TRotator::Quaternion`, `TQuat::Rotator` and `TRotator::Euler` (local source: `D:\UE_5.8\Engine\Source\Runtime\Core\Private\Math\UnrealMath.cpp`). A positive yaw turns +X toward +Y; a positive pitch raises +X toward +Z. Array order `[Roll, Pitch, Yaw]` is UE's XYZ Euler vector order, while the `TRotator` constructor takes `(Pitch, Yaw, Roll)`. Euler angles can change representation at singularities while preserving orientation.

## Scene/template transforms, settings and physics components

For **engine-owned scene or template JSON**, explicitly call `migrateLegacySceneTransforms(source)` from `src/framework/parsers/scene-coordinate-migration.js` and persist the returned **copy** after reviewing it. An unmarked input is considered legacy *only at this explicit LitEngine-format entry point*; calling the helper again on its output is idempotent. For a scene without selected Paper2D entities or world-space Screens, the uncompressed result has this exact top-level marker. Paper2D-only scenes use version 12; scenes with world-space Screens use version 13 and record both selected scopes.

```json
{
  "coordinateMigration": {
    "version": 11,
    "scope": "entity-local-prs-settings-physics-light-particles-zones-bounds-joints-screen-ui-top-left-y-down",
    "basis": "ue-x-forward-y-right-z-up",
    "euler": "unreal-roll-pitch-yaw-xyz-degrees",
    "screenSpaceUiDefaultFields": []
  }
}
```

Each ordinary world entity's local `position`, `rotation`, `scale` is converted. Rotations pass through quaternion basis conversion before becoming UE Roll/Pitch/Yaw XYZ degrees. Compressed scenes expand their field names and both `___1`/`___2` PRS index encodings into ordinary per-entity arrays; shared vector tables are not modified. The original input remains unchanged. The known world-space scene settings `physics.gravity`, `render.skyboxRotation`, `render.skyMeshPosition`, `render.skyMeshRotation`, `render.skyMeshScale`, `render.skyCenter`, and axis-count `render.lightingCells` are converted when present. An omitted `skyCenter` is materialized from the legacy +Y default before conversion so the target file stores +Z explicitly. Collision dimensions/offsets/axis and rigidbody motion factors are converted. Particle emitter extents, wrap bounds, world particle normals, and three-channel velocity curves are converted; vector curves must use three channels with matching time keys. Zone dimensions and custom AABB centers/half-extents on model, render and GSplat components are converted. Joint conversion remaps 6DOF axes and signed limits, spring vectors and equilibria; hinge frames are rotated so their local X primary axis follows the converted legacy axis, and hinge angular limits/motor speed have their handedness reversed. Known markers from versions 1 through 10 upgrade to version 11, 12 or 13 without converting already-migrated world transforms twice. Version 11 marks the 3D and screen-space UI migration; version 12 also records selected Paper2D entities. Version 13 records selected Paper2D entities and world-space Screen roots. Unknown or conflicting markers fail rather than being guessed. A `screen` with `screenSpace: true` and its complete child hierarchy is migrated as a separate pixel-coordinate domain: positions and scales stay in pixels, local rotations are reflected into the top-left/+Y-down UI basis and stored as Unreal Roll/Pitch/Yaw, and element anchors, pivots, margins and text alignment, button hit padding, layout-group alignment/padding/order, and vertical scrollbar values are converted. World-space Screen roots use ordinary 3D basis conversion; their UI descendants keep pixel positions and scales while their local rotations and UI component fields use the same top-left/+Y-down conversion. Missing legacy defaults materialized by migration are recorded in marker metadata so preview can remove them and restore the original scene shape. Nested screens, UI components outside a Screen hierarchy, screen-space particle systems and UI hierarchies containing physics or 3D render components remain unsupported and are rejected. Sprite-bearing scenes are rejected unless their 2D hierarchy is explicitly selected as described below. Script-owned and external asset data remain unchanged because the converter cannot infer their coordinate semantics. Inspect those fields before persisting a migrated file.

For a scene that contains Paper2D-style world sprites, pass `{ paper2dEntityIds: [...] }` as the second argument to `migrateLegacySceneTransforms`. List every transform in each selected 2D hierarchy, including transform-only parents; their old `(X horizontal, Y vertical, Z depth)` values map to `(X horizontal, Z vertical, Y depth)`, and the planar rotation, scale, collision axis, offsets and rigidbody factors follow that basis. The output uses migration marker version 12 and records the sorted IDs in `coordinateMigration.paper2dEntities`; `previewMigratedSceneTransforms` uses that list to restore the legacy scene. All unselected entities and global scene settings still use the 3D conversion above. The helper does not guess which empty parents belong to a sprite hierarchy, and it does not overlap or replace the separate screen-space UI conversion. Selected Paper2D entities may contain sprite, collision, rigidbody, zone and model components; a JSON Model asset referenced by `model.asset` must separately pass through `migrateLegacyPaper2DModel`. Camera, joint, light, particle-system and render components remain unsupported on selected Paper2D entities. UI hierarchies remain a distinct migration scope and cannot overlap the selected Paper2D IDs.

The current `SceneParser` (used by scene, hierarchy and template loading) recognizes version 1 through 13 markers. Unreal applications validate and instantiate the tagged target-basis values directly; legacy applications make a temporary **old-basis preview copy** before instantiating entities. `SceneHandler` also previews migrated settings before applying them to a legacy runtime. `previewMigratedSceneTransforms(tagged)` exposes the whole preview copy explicitly. Loading a tagged scene therefore preserves its old world placement and supported component data while the persisted file has target-basis values; screen-space and world-space Screen UI load with top-left/+Y-down layout semantics in Unreal mode and are previewed in the legacy pixel/layout convention in legacy mode. It does **not** make every renderer, physics backend, component or editor path UE-native. Legacy applications continue loading untagged data as before; Unreal applications reject untagged scene data so its basis is never guessed. Never persist the temporary preview copy in place of the tagged output.

For legacy PlayCanvas JSON animations (versions 3 and 4), call `migrateLegacyAnimationTransforms(source)` from `src/framework/parsers/animation-coordinate-migration.js`. It converts each node key and shared default for position, rotation and nonuniform scale, tags the returned copy, and is idempotent. To select Paper2D nodes in a mixed animation, pass `{ paper2dNodeNames: ['SpriteRoot'] }`; each name must match exactly one animation node. For `animclip` JSON, `migrateLegacyAnimClipTracks(source)` converts graph position, quaternion rotation and scale outputs, including cubic tangents. Pass `{ paper2dEntityPaths: [['Scene', 'SpriteRoot']] }` to select exact Paper2D entity paths in a mixed clip. Both markers preserve selections so parsers can preview the right basis. `JsonAnimationParser` previews tagged data in legacy mode; Unreal mode validates and loads the tagged values directly, interpreting rotation triples as UE Roll/Pitch/Yaw. Unreal mode rejects unmarked JSON animation assets. `AnimClipParser` previews tagged clips in legacy mode and reads tagged values directly in Unreal mode; Unreal mode rejects unmarked clips. Quaternion tracks remain XYZW quaternions and use UE Roll/Pitch/Yaw only when presented as editable Euler values. External GLB animation remains a separate migration path.

For legacy PlayCanvas JSON model v3 assets, call `migrateLegacyModel(source)` from `src/framework/parsers/model-coordinate-migration.js`. It converts node PRS, vertex positions/normals/tangents, triangle winding, bounds, inverse bind matrices and morph deltas into the 3D Unreal basis. For a model authored on PlayCanvas's XY Paper2D plane, use `migrateLegacyPaper2DModel(source)` instead; it maps X horizontal, Y vertical and Z depth to X horizontal, Z vertical and Y depth. Both helpers produce separate validated markers, and `JsonModelParser` previews either marker in legacy applications or consumes the tagged values directly in Unreal applications, assigning Unreal Euler semantics to every graph node. Unreal mode rejects untagged JSON models before allocating GPU resources. Triangle strips and fans are rejected until expanded.

For glTF/GLB import, the parser follows the owning application by default; set `asset.options.coordinateSystem` or pass `{ coordinateSystem: 'legacy' }` to `GlbParser.parse` to override it. Unreal mode converts node transforms, mesh positions/normals/tangents, indexed triangle winding, bounds, morph deltas, skin inverse bind matrices and translation/rotation/scale animation output accessors before resources are created. Parsed nodes and cameras use the selected axis semantics. Downloaded buffer data remains unchanged. The import rejects unsupported geometry encodings, including sparse or quantized spatial accessors, triangle strips/fans, unindexed triangles, compressed geometry and GPU instancing; convert those files to ordinary dense, indexed triangles first.

For GLB export, `new GltfExporter().build(root, options)` follows the root node's coordinate convention by default. Unreal hierarchies are exported in glTF coordinates; pass `{ coordinateSystem: 'legacy' }` to preserve the older engine-basis output. Export copies node translation/rotation/scale, dense float32 position/normal/tangent buffers, triangle indices and skin inverse-bind matrices; source transforms and buffers are not modified. Unreal export currently accepts indexed triangle lists with float32 spatial vertex attributes. It rejects unsupported index formats and non-triangle or unindexed geometry instead of producing an asset with incorrect winding. Pass explicitly selected `AnimTrack` values as `{ animations: [track, ...] }` to export graph local-position, local-rotation and local-scale curves. STEP, LINEAR and CUBICSPLINE data are preserved, including cubic tangents; Unreal values are converted to the glTF basis. Key times must be finite and strictly increasing. Target paths match unique entity-name suffixes inside the exported hierarchy; unsupported component/property curves and duplicate target channels fail export. Tracks are not discovered from `AnimComponent` automatically, and glTF does not preserve animation events or morph-target curves.

For procedural indexed triangle meshes, call `new PlaneGeometry(...).convertToUnrealCoordinates()` (or the same method on another `Geometry`) before `Mesh.fromGeometry`. The method changes positions, normals, tangent handedness and triangle winding in place, preserves UVs and colors, and is idempotent. A legacy ground plane becomes an XY plane with a +Z normal; legacy Y-aligned cones and capsules become Z-aligned. For a Paper2D mesh authored in the legacy XY plane, use `geometry.convertToUnrealPaper2DCoordinates()` to map it to Unreal XZ with Y depth. Geometry records whether it is legacy, Unreal 3D, or Unreal Paper2D and rejects converting between target bases accidentally. The `RenderComponent` and `ModelComponent` primitive type shortcuts now choose separate converted meshes when `entity.coordinateSystem = 'unreal'` is set **before adding the component or changing its type**. The editor's cone and capsule use those converted meshes directly.

For world `SpriteComponent`s, Unreal-coordinate entities use the Paper2D XZ plane. Simple sprite meshes are lazily duplicated and remapped from local XY, including normals and triangle winding; the legacy frame meshes remain unchanged for UI images and legacy entities. The component maps sprite height and pivot offsets onto local Z and keeps local Y for depth. Scene migration converts explicitly selected Paper2D world transforms and sprite physics data. Screen-space and world-space Screen UI use the converted top-left/+Y-down UMG-style fields and runtime behavior in Unreal mode.

A collision component added to an Unreal-coordinate entity defaults its capsule, cone or cylinder axis to local Z. Explicit `collision.axis` values still take precedence. Unreal applications initialize rigid-body gravity to `(0, 0, -9.81)`; legacy applications keep the engine's `(0, -9.81, 0)` default. Directional and spot lights emit along component local +X in Unreal mode, matching UE 5.8.1's `ULightComponent::GetDirection()`; legacy lights retain local -Y. Spot-light bounds follow the same axis. Unreal-coordinate particle components default their world normal to +Z and use +X as the box-emitter initial-velocity direction in both CPU and GPU simulation; legacy particles retain their current defaults. Version 5 scene migration adjusts directional and spot light transforms so their world-space direction is preserved; version 7 adds the joint-frame axis adjustment. Older known scene markers are upgraded once, and legacy previews reverse the adjustments.

For XR ambient light, `XrLightEstimation.sphericalHarmonics` keeps the original WebXR probe-space coefficients. `sphericalHarmonicsWorld` samples the light probe pose each frame and returns those coefficients transformed into the active application world basis, including the Unreal reflection and axis permutation. It returns `null` when the estimate or probe pose is unavailable.

The application, standalone nodes, cameras, scenes and input poses default to Unreal semantics. `new Application(canvas)` selects Unreal by default. Existing projects can keep their old basis by passing `{ coordinateSystem: 'legacy' }`; with `AppBase`, set `app.coordinateSystem = 'legacy'` before `app.init()`. This configures the root and scene, initializes gravity on -Y, and makes subsequently created entities and cameras inherit legacy semantics. In Unreal mode, node identity reports forward +X/right +Y/up +Z, and `lookAt` defaults to world +Z up. `get/setEulerAngles`, `get/setLocalEulerAngles`, `rotate` and `rotateLocal` interpret XYZ as UE Roll, Pitch, Yaw; quaternion setters retain XYZW quaternion inputs. The camera maps +X forward, +Y screen-right and +Z screen-up to the graphics eye basis; perspective/orthographic projection, `screenToWorld`, `worldToScreen`, frustum, and forward-renderer front-face handling share that reflected basis. Standalone `Pose` instances use Unreal semantics by default; `FlyController`, `OrbitController` and `FocusController` retain the attached pose's convention. Unreal poses use local +X forward, UE Roll/Pitch/Yaw slots, and positive orbit distance behind the camera along local -X. The editor viewport creates Z-up scene objects and supports Unreal-aware camera movement, selection/picking, transform gizmos, Roll/Pitch/Yaw inspection, and XYZ scaling. The Unreal graphics example was browser-smoke-tested on WebGL2 and WebGPU, including visible converted primitives and lighting. In Unreal mode, scene and template JSON must be tagged by `migrateLegacySceneTransforms`; loading preserves its Unreal-space values, upgrades known older marker versions and rejects unmarked scene data. Legacy applications continue previewing marked data in their old basis.

## Open boundaries and compatibility

- **World-space Screen components:** a complete child hierarchy rooted at `screenSpace: false` is supported by migration marker version 13. The Screen entity's own transform converts as a 3D world transform; child UI positions and scales remain in pixels, while UI rotations and UI component values convert to top-left/+Y-down semantics. Unreal runtime places the plane in the YZ plane, maps UI horizontal to local +Y and vertical-down to local −Z, and uses the same basis for element bounds and hit testing. Older version 11/12 markers with world-space Screens are rejected because they cannot say whether the Screen root was already converted.
- **Screen-space UI / UMG:** a complete subtree rooted at `screenSpace: true` is supported in Unreal mode. Migration converts legacy bottom-origin anchors, pivots, margins, text alignment, button hit padding, layout-group alignment/padding/reverse order, and vertical scrollbar values to top-origin/+Y-down semantics. Pixel positions and scales remain in their pixel domain; local rotations are reflected and stored using Unreal Euler semantics. Runtime element bounds, screen projection, layout flow, vertical scrolling, text glyph orientation and pointer hit testing follow the same convention. The marker records implicit legacy defaults so `previewMigratedSceneTransforms` can restore the original data. UI components outside a Screen hierarchy, nested screens, screen-space particle systems, and UI hierarchies containing physics or 3D render components remain unsupported.
- **Paper2D assets:** selecting `paper2dEntityIds` converts scene transforms and supported `sprite`, `collision`, `rigidbody`, `zone` and model bounds. The JSON Model asset referenced by a model component must separately be converted with `migrateLegacyPaper2DModel`. The selection rejects `button`, `screen`, `element`, `layoutchild`, `layoutgroup`, `scrollbar`, `scrollview`, `camera`, `gsplat`, `joint`, `light`, `particlesystem` and `render` components. Runtime sprite mesh remapping covers generated simple and sliced/tiled frame meshes; indexed procedural geometry is also supported. JSON model v3 geometry, nodes, skins and morphs can be migrated explicitly; JSON animations and animclips can be converted with the explicit name/path options above. The scene migrator does not infer asset or animation ownership from scene IDs. There is no Paper2D sprite-atlas importer/exporter or Paper2D animation export path. The general GLB importer/exporter uses the 3D Unreal basis.
- **User-authored data:** the scene converter changes only the documented transform, physics, light, particle, joint, bounds and scene-setting fields. Script attributes and arbitrary application-defined component data are passed through because their numeric values have no known coordinate meaning. External assets require a supported explicit converter (GLB, JSON model, JSON animation or animclip) or a caller-owned conversion step.
- **Interactive graphics QA:** engine tests cover coordinate math, screen-space UI bounds, pointer hit padding, layout, scrolling, text orientation, world-space Screen plane mapping and hit testing, scene migration, and selection logic. The Unreal example was visually exercised on WebGL2 and WebGPU, including world-space Screen rendering, +Y / +Z direction markers and opposing camera views in separate left/right viewports. The local editor's Z-up sample scene and Move, Rotate and Scale gizmos were visually checked; X/Y/Z rotation updated Roll/Pitch/Yaw independently, each non-uniform scale handle changed only its matching field, and Undo restored the sample scene.
- **Default switch and compatibility:** `3.0.0-beta.0` switches the application and coordinate-aware object defaults to Unreal, as required for a breaking default change. Existing projects can opt into `legacy` before initialization; old untagged scenes and JSON models remain loadable in that mode. Projects moving to Unreal must migrate scene/template data with `migrateLegacySceneTransforms` and use a supported asset converter before loading. Asset handlers follow the owning application's convention unless a container asset explicitly overrides `coordinateSystem`. This compatibility path is covered by tests. Unsupported components and asset formats listed above still require conversion or must remain in legacy mode.

Do not infer external file coordinates from numeric values or treat UI pixels, Paper2D geometry and 3D world transforms as one convention.
